# AFTER HOURS — 首个 3D 无限练习原型

状态：设计方向已获批准；本文待用户进行书面规格评审。尚未开始产品实现。

## 1. 产品目标与停止条件

让玩家通过自然上划学会投篮，看懂失误，并愿意立即再投。真实 3D 是手感的基础，物理系统复杂度本身不是目标。

本次只交付一个可连续投 20–30 球的无限练习原型：篮球、篮圈、篮板、简单球场、稳定透视相机、Rapier 物理、触摸/鼠标上划、可靠计分和快速补球。HUD 只显示本次练习的命中数/出手数、简短反馈和重新开始。没有失误次数限制，没有 Game Over。

交付可运行原型、验证结果、竖屏录屏及调参入口后停止，等待用户亲自试玩。约 50–70% 是熟悉操作后、合理手势的暂定真人命中率目标；自动化命中率不代表达标。若手感仍令人困惑，下一轮先修手感。

三次失误、+1 积分、最佳分数持久化和一键重试属于后续街机模式；本次不实现。响应网、音效和环境打磨同样推迟到首次试玩之后。首版使用静态轻量网帮助看清穿筐。

## 3. 技术与职责

使用 React、TypeScript、Vite、Three.js、React Three Fiber、React Three Rapier、Drei、Zustand。实现时查验当前 peer dependencies，选择兼容组合并锁定解析版本；不照搬参考仓库的旧版本组合。

模块边界保持小而直接：

| 位置（相对于 prototype-3d/） | 职责 |
| --- | --- |
| `src/config.ts` | 所有几何、物理、输入、相机、恢复与画质参数 |
| `src/domain/launch.ts` | 纯函数：手势归一化、宽容映射、弹道速度 |
| `src/domain/scoring.ts` | 纯函数：有序向下穿越与每球一次计分 |
| `src/domain/shot.ts` | 单球生命周期、终止条件和依据实测的失误分类 |
| `src/input/` | Pointer Events、指针捕获、取消、尺寸快照 |
| `src/scene/` | 相机、球场、篮筐、球、固定步进与碰撞记录 |
| `src/store.ts`、`src/ui/` | 练习统计、少量阶段状态和 DOM 控件 |
| `src/debug/` | DEV 练习记录、只读检查接口与 JSON 导出 |
| `tests/` | 纯逻辑、真实 Rapier 与浏览器输入验证 |

Rapier 保存飞行中的位置/速度；物理步进直接向判分与日志提供采样。Zustand 只保存需要刷新 UI 的离散状态。每帧位置、轨迹数组和碰撞数据不经过 React state。

## 4. 一个几何与物理约定

单位为米、秒、千克，Y 向上，球从正 Z 朝篮圈发射。以下是集中配置的起始调参值，不是已经验证的最终手感：

| 参数 | 起始值 |
| --- | --- |
| 重力 | `(0, -9.81, 0)` |
| 球中心起点 | `(0, 1.35, 4.2)` |
| 球半径 / 质量 | `0.12 / 0.62` |
| 篮圈中心 / 内半径 / 管半径 | `(0, 3.05, 0) / 0.24 / 0.018` |
| 篮板中心 / 宽高厚 | `(0, 3.65, -0.43) / (1.8, 1.05, 0.06)` |
| 球恢复系数 / 摩擦 | `0.65 / 0.35`，按实测接触调节 |
| 基准弧顶高度 | `4.1` |
| 固定物理步长 | `1/120 s`，限制追帧，记录成本后再决定是否降为 60 Hz |

视觉球与显式 BallCollider 使用同一半径；动态球开启 CCD。地面、篮板和篮圈固定。篮圈显示为 torus，其主半径由内半径加管半径推导；使用 32 段沿同一圆环排列的 capsule 近似碰撞，端点共享、开口真实中空。显示调试几何以检查近似误差；不使用封住开口的凸包。

网使用一次创建的简单线段几何，无碰撞体。首版不做关节网、软体、复杂环境或反射效果。球使用原创球面接缝和简单材质，不把现有 2D 球图直接当 UV 纹理。

## 5. 自然上划与物理发射

只接受当前准备球附近的宽松触摸区域内开始的主指针。统一 Pointer Events，设置 touch-action，捕获指针；pointercancel、lostpointercapture、切后台和尺寸变化取消未完成手势。额外触点、按钮操作、轻点和向下拖拽不消耗出手。

按 pointerdown 时的实际游戏区域宽高，将 dx/宽、向上 dy/高归一化。pointerup 的真实终点决定发射，pointermove 只供提示；相同起终点和持续时间不因事件数量变化而改变速度。尺寸变化取消本次瞄准，下一次使用新尺寸。

纵向距离控制射程偏差；普通上划区间压缩灵敏度，但保留连续变化。横向设小死区并采用平滑、有限的响应，容忍无意偏移；明显斜划仍偏左/右。首轮以高度约 20–40% 的上划作为宽容调参起点，不要求固定像素或精确角度。较弱和较强手势分别能产生可复现的短球与长球。持续时间记录到日志，首版不用于放大力度，避免手速差异主导命中率。

基准速度由实际起点与篮圈位移求解：设起点高度 y₀、目标高度 yₜ、弧顶 A、重力绝对值 g，则 vy = sqrt(2g(A−y₀))，到下降目标面的时间 t = vy/g + sqrt(2(A−yₜ)/g)，vx = Δx/t、vz = Δz/t。手势映射为有界的目标横向/纵深偏差，仍用同一解算求发射速度。

准备球处于固定待发状态；释放时转为动态球并设置一次线速度和适量后旋。从这一步起 Rapier 独立推进位置与碰撞，直到球被清理。没有飞行中吸附、位置插值、目标纠正、随机散射或按手势直接判进。基准轨迹是发射帮助，球仍必须实际通过开口。

## 6. 可靠判分与可解释失误

每个物理步读取球中心前后位置并做扫掠平面穿越。判分流程为：来自上方 → 向下穿过篮圈平面且球半径能通过实际开口 → 继续下降越过下确认面 → 本球计一次命中。确认面放在篮圈管与球半径下方，允许正常斜向穿网；不要求球在篮圈以下仍保持正中心。

向上穿过不记分；单独侧入下确认区不记分；落地后反弹入筐不记分。有效擦板、碰前后沿再入篮可以计分。篮圈、篮板接触标记来自真实碰撞事件，不由预期轨迹生成；纯净空心球不得触发人为碰圈事件。

HUD 立即更新命中数，短文案区分空心/碰圈后进/擦板后进。失误优先依据实际下降到篮圈高度时的横向与纵深位置，结合真实接触给出“偏左/偏右/偏短/偏长”或“打铁/擦板未进”。已经反弹、缺少可靠采样时采用接触或中性反馈，不把输入预测当作实际结果。所有出手仍保留完整诊断数据。

## 7. 无限练习与快速恢复

球状态为 Ready → Aiming → Flying → Resolved；新球不必等旧球停止反弹。确认命中后约 350 ms 准备下一球；确认失误后约 150 ms 准备下一球，均按仿真时间计时并可调。真实接触仍可能改变结果时继续观察，不仅凭发射速度提前判失误。

地面接触、离开可恢复的球场边界、下降到已不能入篮的低处且远离篮筐，或达到最长 5 秒仿真寿命，可终止未命中球。终止后取消该球计分资格；旧球继续自然运动直至清理。

最多同时保留 3 个动态球；旧球间不互相碰撞，也不影响新球。按年龄淘汰已终止球，重开练习时统一清理球、计时和判分状态。每球与每次练习有独立 ID，防止上一局回调污染新局。无限练习不保存历史最佳，不在第 3 次失误时中断。

## 8. 移动构图与资源约束

默认竖屏全可用区域，适配安全区。相机起始约 `(0, 2.05, 6.1)`，看向 `(0, 2.1, 0)`，竖向视角约 54°；以真实投射检查前景球、篮圈及基准弧顶是否可见，再集中调参。瞄准和飞行时相机固定，不跟随球。

验收 320×568、400×712、430×820；桌面使用有宽度上限的竖屏游戏区，避免宽屏裁切。旋转或窗口缩放更新投影和输入区域，不改变世界几何或已释放球的速度。画面保持简单但可辨认：深色球场、清晰球与暖色篮圈、浅色网和板框、少量 teal/amber 灯光。

DPR 上限 1.5，最多一个低成本阴影光源；复用几何与材质，避免逐帧重建网格。页面隐藏暂停渲染、物理和恢复计时，返回后丢弃累计时差并显式继续。WebGL/物理初始化失败显示可读的重试提示；事件监听、物体、几何和计时器在退出时清理。没有实机测试前不宣称手机性能达标。

## 9. 验证与首次试玩交付

按最短可玩路径实现：独立工具链和可见几何 → 弹道与真实接触 → 判分 → 宽容上划 → 快速补球及无限练习。测试随对应模块完成，不先制作精致环境。

- 纯逻辑：弹道解在下降时到达目标、有限速度/无效输入、横向容忍与明显偏差、弱/强手势、事件数独立、尺寸归一化、取消手势、每球一次/仅向下/拒绝侧入与反弹计分。
- 真实 Rapier：球从正常起点按计算速度飞行，测空心、前沿、后沿、篮板和明显失误；检查穿透、碰撞位置与可视几何一致。物理接触后的反弹不由模拟事件代替。
- 浏览器：通过实际鼠标和触摸指针输入出手，覆盖三个竖屏尺寸及桌面、resize、取消、隐藏恢复、快速重开和连续 30 球的物体/监听器清理。验证生产构建不暴露 DEV 接口。
- 录屏：典型命中、空心、前沿失误、后沿失误、擦板和连续出手，均由真实指针操作发射；对应 JSON 保存速度、接触与结果。不得注入得分或瞬移球制作演示。

DEV 模式记录每次人类/自动化出手的来源标签、练习/球 ID、原始手势和持续时间、区域尺寸、映射结果、起点、速度、固定步进轨迹、碰圈/板记录、判分过程和结果分类。通过按钮复制 JSON，剪贴板失败可下载。每次练习保留最近 100 球，轨迹按固定频率采样并设上限；计数不会因此重置。

交付应包括分支、文件变更、运行命令、集中配置说明、build/lint/test 结果、录屏与日志、已知限制和资产声明。交付后先由用户完成 20–30 次自然手势试玩并描述失误是否清楚；再判断是否调整手感或推进后续模式。

## 自审

已明确首版为无限练习，三失误模式与响应网/音效后置；基准弹道只影响发射，飞行与碰撞由 Rapier 控制。判分区分上方进入、开口穿越和下方确认；快速恢复只发生在结果确定之后。所有数字为集中配置的起始假设，实际手感与 50–70% 目标留给真人验证。无未决产品问题；实现前需完成本书面规格评审及实施计划评审。
