# 篮球投篮游戏 MVP 设计

状态：待用户审阅。本文记录已提出的架构和默认产品选择，不代表代码已经实现。

## 目标与范围

构建可在 VS Code 本地运行的、竖屏移动优先的 2D 浏览器篮球游戏。首要验收标准是投篮反馈清晰、操作可学习，让玩家愿意再投一次。长期目标是通过 Capacitor 发布移动应用，但本轮不添加 Capacitor。

MVP 包含主菜单、选关、10 个数据配置关卡、投篮、可靠入篮判定、积分、有限次数、胜负结算、星级、金币、四类装备升级、本地保存和基础反馈。

不包含 React、登录、Firebase、后台、云存档、排行榜、成就、每日挑战、广告、内购、皮肤、通行证、多人游戏及商店接入。美术使用原创几何图形和虚构装备，不使用真实球队、品牌或球员形象。

## 技术与依赖方向

使用 TypeScript、Vite、固定版本的 Phaser 3、Phaser 内置 Matter、Vitest、ESLint、Prettier。浏览器 UI 使用轻量 HTML/CSS，不引入 UI 框架、ECS 或全局状态管理库。

- `domain/`：纯 TypeScript，负责投篮生命周期、分数、关卡结果、进度、奖励和购买，不依赖 Phaser、DOM 或存储。
- `game/physics/`：拥有 Matter 物体与步进，输出位置、速度和接触记录。
- `game/scenes/`：负责生命周期、场景切换与装配，不包含价格或奖励规则。
- `game/entities/`：球、篮筐、球场的物理与显示适配。
- `game/input/`：统一鼠标、触摸和取消行为。
- `game/systems/`：轨迹预览和视听反馈。
- `game/ui/`：DOM 菜单、HUD、暂停层、装备卡和结算视图。
- `app/`：连接领域、场景与服务，协调当前游戏和玩家进度。
- `services/`：存储、音频、触觉反馈接口与浏览器实现。
- `data/`：关卡、装备、经济、评分、物理参数。

通过普通函数调用和少量类型化事件通信。Matter 是物理状态来源，领域模型是玩法和进度状态来源。表现动画不控制积分或奖励是否生效。

## 场景与数据

保留 BootScene、PreloadScene、MainMenuScene、LevelSelectScene、GameScene、LevelResultScene、EquipmentScene。场景退出时清理其 DOM、监听器、计时器和动画。

LevelConfig 包含 id、targetScore、totalShots、rewardCoins，以及可选的归一化 hoopPosition、scoreMultiplier、受支持的 modifiers。配置启动时验证；不静默接受未知修改器。初期通过位置、目标和次数制造变化，不要求移动篮筐或风力。

前三关使用原始规格的 10 次/10 分、10 次/16 分、12 次/24 分；其余七关在投篮手感稳定后配置。所有关卡都必须可用初始装备完成。

## 投篮与物理

采用侧视球场、圆形篮球、两个篮圈碰撞体、篮板和地面。网是视觉动画和判分区域，不做绳网物理。

从球附近开始向预期方向拖拽，距离控制力度，松开投球。采用宽松触摸命中区、最小拖拽阈值、最大力度限制和短虚线预览。只跟踪一个指针和一个活动篮球。

状态为 Ready → Aiming → InFlight → Resolving → Ready 或 LevelFinished。只有有效发射才扣次数。取消拖拽、失焦或瞄准时暂停不扣次数。最后一球仍在飞行时不能失败。

使用固定物理步进和有限追帧；原型先评估 120 Hz 的碰撞稳定性及手机成本。恢复页面时丢弃暂停累计时间。暂停同步冻结物理、玩法计时和发射输入。球入篮、确定出界、地面接触后的终止条件或仿真时间超时结束本次投篮。

轨迹预览复用发射映射和物理参数，只提示初段飞行。通过实际无碰撞投射样本检查预览误差，避免独立维护另一套弹道规则。

## 入篮与评分

独立 detector 接收每步前后位置、速度、球半径、篮筐位置和接触记录。球必须从上方接近，在开口内向下跨过篮圈平面，再继续向下跨过确认平面。使用线段扫掠检测越界，避免高速跳过传感区域。

开口检查考虑球半径。向上穿过、侧面进入、篮圈底部撞击、无效退出和地面反弹不计分。每个 shotId 最多一次入篮事件。合法擦板或碰圈后入篮仍可计普通球。

分类互斥，优先 Perfect、Swish、Normal：

- Normal：合法入篮且此前碰圈或碰板，基础 2 分。
- Swish：合法入篮且无碰圈碰板，基础 3 分。
- Perfect：Swish 且中心偏差和入篮角度满足更严格阈值，基础 4 分。

Perfect 使用空间和角度容差，不增加时间节奏条。袖套扩大此分类容差，不改变弹道。阈值集中配置，原型测试后确定具体调参值。

所有装备分数调整和关卡倍率在单个评分函数内处理，最后统一向下取整。连续命中计数可提供动画，MVP 初始关闭额外连击分数，以保持平衡可解释。

## 关卡结算

达到目标锁定通过状态，但继续使用剩余次数争取星级。最后一球结束后结算。星级阈值为目标、ceil(目标 × 1.2)、ceil(目标 × 1.4)，倍率可配置。

失败展示当前分数、目标、重试和返回；成功展示分数、星级、金币、下一关和装备入口。最后一关返回选关，不解锁不存在的关卡。

## 进度、经济与装备

PlayerProgress 保存 schemaVersion、highestUnlockedLevel、coins、各关最佳星级、已拥有装备、装备等级和当前装备 ID。最佳星级只增不减。每个成功 runId 只应用一次奖励和解锁，结果视图重复挂载不能再次发奖。

成功重玩可再次赚取金币，失败不发金币。奖励由关卡基础奖励、星级奖励和装备奖励系数统一计算，最后向下取整。奖励表和价格表集中存储，避免 UI 定价。

四类装备初始各拥有一件 1 级物品，最高 5 级。升级费用依次为 100、250、500、1000。装备定义、等级、属性和装备槽分离，不提前实现物品商店。

- 鞋：轻微过滤输入抖动，不引入基础随机误差，不吸附目标。
- 袖套：扩大 Perfect 判定容差。
- 篮球：使力度响应更宽容，最大力度不变。
- 篮筐/网：小幅增加金币收益，不改变碰撞几何。

calculateStats 在关卡开始时生成不可变属性快照。任何装备都不能把失误自动修正为命中。购买统一校验所有权、等级上限和余额，一次生成扣币和升级后的进度。

## 存储与移动适配

ProgressStore 隔离 load/save；本轮仅实现版本化 localStorage。启动时校验 JSON 和字段，处理旧版本、损坏数据和不可写存储。不得静默覆盖无法识别的较新版本存档。写入失败明确提示未保存，不声称持久化成功。

奖励和购买保存整个进度快照，避免金币与装备分开写入。云端同步和冲突解决不属于这个抽象自动提供的能力。MVP 只在结算和购买后保存，不恢复半局比赛。

球场使用固定 9:16 逻辑空间，适配可用屏幕；物理不随设备尺寸改变。HUD 使用响应式锚点和 safe-area Insets。桌面为居中的手机比例视口。额外触摸不启动第二次投篮，后台暂停，旋转后保持控件可用。

## 反馈与资产

FeedbackController 消费 RimHit、BasketScored、LevelCompleted 等事件。加入球旋转、视觉篮圈反应、轻微震动镜头、浮动分数、Swish 反馈和 Perfect 粒子。物理篮圈不因视觉动画移动。

AudioService 和 HapticsService 使用可替换接口，缺资源或能力时使用占位/no-op。初期不运行收费资产生成、资产导入、离屏 GPU 捕获或硬件测量工作流；需要时再使用 Game Development Studio 对应工具。

## 实施顺序与验收

1. 基础项目、工具链、场景壳、视口与 README：开发、构建、类型、lint、测试命令可运行。
2. 投篮原型：球场、拖拽、发射、物理和预览，鼠标与触摸一致。
3. 手感调试：力度、重力、弹性、重置速度和基础反馈；用户实际试玩后再扩大功能。
4. 入篮与评分：覆盖向上、底部、侧入、高速、重复越界、落地反弹和合法擦板场景。
5. 一个完整关卡：次数、暂停、星级、胜负、重试，最后一球正确结算。
6. 进度与存储：选关、解锁、最佳星级、重载恢复和坏存档处理。
7. 经济：奖励只应用一次，重玩收益明确。
8. 装备：四类升级、统一属性和可验证购买。
9. 十关：基础装备可通关，调节奖励和难度。
10. 移动体验：安全区、后台恢复、反馈、真实手机试玩和场景资源清理。

每步保持小而可审阅的 Git 提交，README 持续记录安装、命令、架构、控制方式、已实现功能和下一步。

Vitest 覆盖领域边界、评分取整、星级阈值、投篮取消、最后一球、重复奖励、余额不足、最高等级、存档校验与迁移。真实 Matter 集成测试验证录制发射输入和不同渲染帧率下的结果。浏览器及手机试玩验证触摸、安全区、切后台和长时间运行；纯逻辑测试不代替手感验收。

## 自审结果

已将即时过关与星级追分的冲突统一为用完次数后结算；已明确 Perfect 不引入新的时间操作机制；已隔离物理、判分、表现和持久化。具体手感参数和其余关卡数值属于原型测量后的调参工作，不影响模块职责。当前无实现代码。
